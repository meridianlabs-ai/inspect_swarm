Scoring

Overview

A swarm is scored by the task’s own scorers. The swarm is the task’s solver, so the scorers run after it, on the swarm’s output and on whatever the members left in the sandbox, as they would after a single agent. Inspect Swarm adds no scorer of its own; it records what the swarm did, so analysis can read it beside the scores.

The answer and the result record

The answer

The controller’s final rule chooses the swarm’s answer from the members’ submissions:

  • first, the default: the member that submitted earliest, by the swarm’s clock, with ties broken by roster order.
  • last: the latest submission, again with ties broken by roster order. leaderless(stop_on_submission=False, final="last") gives it, for a team whose members build on each other’s work (Controllers).

A controller of your own can also choose the answer itself, with choose_answer(), in place of the rule (Controllers). A member that ended any other way than submitting is never chosen (Members). When no member submitted, the answer is empty.

The swarm’s output is the chosen member’s ModelOutput, unchanged, so the scorer sees what it would have seen had that member run alone. The sample’s messages are its input followed by the answer’s message, whose metadata["inspect_swarm"] names the mode and the chosen member. Each member’s own conversation is in its timeline.

The result record

When the swarm ends, it writes a record of what it did to the transcript, as an evidence event in the swarm’s span. Read it with swarm_result(state) in a scorer, or swarm_result(sample) for a sample read from a log, which needs the sample’s events and attachments. The record is:

{
  "version": 1,
  "members": [
    {"name": "react-1", "role": null, "choose_name": false, "state": "ended", "status": "submitted", "submitted": true, "time": 41.2, "sandbox": null, "gate_checks": 0, "gate_passes": 0, "first_pass_time": null},
    {"name": "react-2", "role": null, "choose_name": false, "state": "ended", "status": "swarm_cap", "submitted": false, "time": 57.9, "sandbox": null, "gate_checks": 0, "gate_passes": 0, "first_pass_time": null}
  ],
  "final": {"mode": "first", "member": "react-1", "reason": null, "provisional": false}
}
  • A member’s state is pending (never started), running or ended, and status says how it ended (Members).
  • time is seconds from the swarm’s start to the member’s end.
  • choose_name is true for a member that chose its own name (Members). name is still the swarm’s name for it; the name it chose is in its transcript.
  • sandbox is the member’s own sandbox, or null when it shares the sample’s.
  • gate_checks, gate_passes and first_pass_time count the member’s in-loop checks (Checks during the run).
  • final.mode is first, last or controller, and final.member names the chosen member. Under controller, final.reason is the reason the controller gave. With no submission, mode and member are null and final.reason is "no_submissions".

The event adds "type": "result_record" and an "id", which the swarm also puts in the sample store under inspect_swarm:result_id, so that swarm_result() finds the record of the store it is given. If a limit, error or cancellation ends the swarm before it finalises its answer, the record has the answer so far with provisional: true, and that submission is the sample’s output: the first submission so far, the latest under last, or the controller’s choice once it has made one.

swarm_result() returns None when no swarm ran in the sample. It raises ValueError for a sample it cannot read the record of: one read without its events or attachments, one written by an inspect_swarm that kept the record in the store under inspect_swarm:result, or one that holds a swarm’s events but whose store names no record, as for a sample recovered from a crashed eval.

The record belongs to the swarm

Only the swarm writes the record and inspect_swarm:result_id. Task code (tools, member builders, controllers, scorers) must not write that key or an event with source inspect_swarm. Member names, roles and sandboxes, and a controller’s choose_answer() reason, must be text that a log keeps as it is: not beginning with attachment:// or tc://, which a log reads as a reference to an attachment, not a base64 data: URI, which a log removes when images are not logged, and valid UTF-8. The swarm does not write a record that holds such text, and its end raises ValueError.

There is no record while the swarm runs, so no member can read another’s results from it. A scorer that reads it after the swarm is how a task finds each member’s sandbox (Per-member sandboxes). A tool that reads the transcript sees every member’s model and tool calls anyway. That is a channel between members outside the swarm’s channels, and the swarm records no evidence of it.

Scoring what members leave

A scorer that reads the sandbox, rather than the answer, scores what every member left there. With the default leaderless, the swarm stops the other members at the first submission, so what they were doing is left half done. When the scorer reads a shared artifact, let every member run to its end with leaderless(stop_on_submission=False) (Controllers). The swarm returns after every member and its background work have ended, so the scorer sees the sandbox as the members left it.

examples/shared_sandbox.py scores a script that the members build together in a shared container.

Per-member sandboxes

With per-member sandboxes, the scorer still runs outside every member, where sandbox() is the sample’s default. A scorer that grades the members’ work names each member’s sandbox. The result record says which member used which, so the scorer can read it rather than repeat the roster:

@scorer(metrics=[accuracy()])
def tests_pass() -> Scorer:
    """Run the task's tests in each member's sandbox."""

    async def score(state: TaskState, target: Target) -> Score | None:
        # the record exists once the swarm has ended; a member's react(attempts=...)
        # or live control scoring calls this scorer during the solve
        if not state.completed:
            return None
        record = swarm_result(state)
        assert record is not None, "the task's solver is a swarm"
        passed = [
            m.name
            for m in record.members
            if (await sandbox(m.sandbox).exec(["sh", "/tests/run.sh"])).success
        ]
        return Score(value=CORRECT if passed else INCORRECT, metadata={"passed": passed})

    return score

A check can also run in a shared service rather than in each member’s sandbox. examples/proof_swarm.py mounts each member’s /workspace read-only in a comparator service, at /answers/<member>, and checks an answer there with one command:

async def run_check(member_sandbox: str) -> tuple[bool, str]:
    """Check the answer a member left in its sandbox, with the comparator: whether it is a proof, and why."""
    result = await sandbox("comparator").exec(
        ["python3", "-c", VERIFY, f"/answers/{member_sandbox}/answer.txt"],
        timeout=60,
    )
    return result.success, result.stdout.strip() or result.stderr.strip()

VERIFY exits 0 only for a proof. Its scorer, any_member_proved(), calls run_check() for every member in the result record. A member that wrote a valid answer but was stopped before it submitted still passes, which is why the scorer grades every member’s work rather than only the chosen member’s.

Checks during the run

A task’s scorer can also run inside a member, as react(attempts=...) runs it on each submission. For each member, the swarm counts these checks of its own submissions, made in its own loop with the task’s first scorer:

  • gate_checks: how many submissions were checked.
  • gate_passes: how many of those passed, a score of 1.0 under Inspect’s default value_to_float().
  • first_pass_time: the swarm time of the first pass.

They are in the result record and the metrics. A member with its own score_value can pass its own gate where the count does not, since the count assumes the default converter. Inside a member, a scorer’s sandbox() is the member’s own.

A scorer that runs during the solve, under react(attempts=...), the other attempt loops or live control scoring, cannot read the result record: swarm_result() raises while a swarm in the sample runs. Such a scorer returns None until state.completed is True, as the per-member sandboxes example does. Inspect drops a None score, so the task also needs a scorer that returns a value during the solve, since an attempt loop fails when it gets no score. List that scorer first: the swarm counts checks from the task’s first scorer.

Comparisons

The swarm’s score is the task’s scorer on the swarm’s answer, or on what the members left for a scorer that reads the sandbox. Compare it with:

  • A single agent at the same budget. A swarm of one, swarm(members=agent, channels=[]), runs one agent under the swarm’s rules with the same records (Members), so both arms have a ledger. Unlike a plain agent, it returns an empty output when its member does not submit.
  • Epochs of a single agent, through Inspect’s own reducers on the task’s scorer, such as mean, max and pass_at_k:
from inspect_ai import Epochs, Task, task
from inspect_ai.agent import react
from inspect_ai.scorer import match
from questions import QUESTIONS

from inspect_swarm import swarm


@task
def single_agent() -> Task:
    return Task(
        dataset=QUESTIONS,
        solver=swarm(members=react(), channels=[]),
        scorer=match(),
        epochs=Epochs(4, ["mean", "pass_at_4"]),
        token_limit=50_000,
    )

pass_at_k and max choose with knowledge of the target, and the swarm’s answer rule does not, so they are upper references, not like-for-like comparisons.

Compare arms on the cost the log records, not on the caps (Analysis). team@k, the mean member and best@k on graded scores need each member’s own score, which Inspect Swarm does not record yet; best@k can be computed from per-epoch values in samples_df().
